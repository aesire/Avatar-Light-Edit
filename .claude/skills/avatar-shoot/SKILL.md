# 아바타 촬영

`editor/Tools/Shoot`의 창 없는 촬영 도구로 한다. 장면 형식은 [SHOOT.md](SHOOT.md)를 먼저 읽는다. 명령은 `editor` 폴더에서 실행한다. `bin/Shoot.dll`이 없으면 `sh build.sh shoot`.

컴퓨터 사용 도구로 에디터를 조작하지 않는다. 장면 파일이 더 빠르고 결과가 매번 같다.

## 순서

1. **아바타 찾기.** 사용자가 경로를 주지 않았으면 `dotnet bin/Shoot.dll avatars`. 사용자가 고친 상태를 찍어야 하면 세션(`.alesav`)을 받는다. 어느 아바타인지 애매할 때만 묻는다.
2. **아바타 보기.** `inspect`로 표정·렌더러·뼈를 본다. 표정을 직접 만들 때만 `--shapes 찾을글`로 필요한 이름을 찾는다 (전체 목록은 길다).
3. **기획.** 용도(프로필·썸네일·SNS·설명용), 비율, 분위기를 정하고 샷을 3~6개로 나눈다. 사용자가 세세히 정하지 않았으면 직접 정하고, 결정한 내용을 장면의 `brief`에 적는다. 샷마다 다른 안을 넣는다 — 구도·각도·조명·표정 중 하나 이상이 달라야 비교할 뜻이 있다.
4. **장면 쓰기.** 작업 폴더에 `<이름>.scene.json`으로. 공통 값을 위에, 장마다 다른 값만 `shots`에 쓴다.
5. **시안.** `run <장면> --draft`. `errors`가 있으면 제안된 이름으로 고쳐 다시. `_sheet.png`(한 장이면 그 사진)를 읽어 **직접 본다**.
6. **고치기.** 아래 "볼 것"으로 판단해 장면만 고쳐 다시 `--draft`. `--only 장이름`으로 고친 장만 찍으면 빠르다. 한 번에 한두 가지만 바꿔야 무엇이 효과였는지 안다.
7. **완성본.** 고른 장만 `run <장면> --only a,b`. 완성본을 읽어 손·얼굴을 확대해 볼 필요가 있으면 `camera.bone`으로 시안을 더 찍는다. 끝나면 파일 경로를 사용자에게 알린다.
8. **에디터로 넘기기.** 사용자가 이어서 고치고 싶어 하면 `edit <장면> --only 장`으로 그 상태의 에디터를 연다. 트래킹·말하기·오버레이는 안 넘어가고, 배경 등은 그 PC의 에디터 설정으로 남는다고 말한다.

## 볼 것

- **포즈:** 팔꿈치·무릎이 꺾이면 안 되는 쪽으로 꺾이지 않았는가, 손이 몸·옷을 뚫지 않는가, 발이 바닥에 닿는가, 어깨가 옷을 찢지 않는가. 양손이 똑같으면 딱딱하다 — 머리를 살짝 기울이고 무게를 한쪽 다리로.
- **표정:** 눈이 뚫리거나 입이 찢어지지 않는가. 기본 표정 이름이 있으면 그것부터 쓴다. 제스처 표정(`Fist`, `Peace` 등)은 손 모양과 무관한 얼굴이다.
- **구도:** 머리 위·손끝이 잘리지 않는가, 발목·무릎·손목처럼 관절에서 자르지 않는가. 인물은 `fov` 20~30, 얼굴은 정면보다 `angle` ±15~30이 입체적이다.
- **조명:** 툰 셰이더는 빛이 세면 금방 하얗게 뜬다 — 얼굴이 날아가면 `front`·`intensity`·`ambient`를 낮춘다. 역광에는 `front`로 얼굴을 메운다. 프리셋 `sunset`처럼 색이 강한 빛은 피부색을 보고 판단한다. 앞머리 그림자가 지저분하면 `accessoryShadows`를 끈 채로 둔다 (기본 끔).
- **배경:** 인물과 색이 겹치면 윤곽이 묻힌다. 바닥색은 조명을 받아 적은 색보다 달라 보인다.
- **후처리:** `post`를 적으면 블룸이 0.6으로 켜진다. 원치 않으면 `"bloom": 0`. 크로마키(`avatarOnly`)에는 `post`를 쓰지 않는다.

## 주의

- 사람에게 이 기능이 보이지 않게 둔다: 앱 화면·README·CHANGELOG·CLAUDE.md에 적지 않는다. 고친 내용은 SHOOT.md의 작업 기록에 적는다.
- 머슬 값은 체형마다 결과가 다르다. 함께 넣은 자세도 시안으로 확인한다. 좋은 자세를 찾으면 `Tools/Shoot/poses/<이름>.pose.json`으로 저장을 제안한다.
- 기획을 사용자에게 먼저 확인받는 것은 사용자가 원할 때만. 시안을 보여 주며 묻는 쪽이 빠르다.
- 웹캠·마이크는 사용자가 원할 때만 켠다. `overlay on`은 사용자 화면(방송 중일 수 있다)에 바로 보이므로 부탁받았을 때만, 다 쓰면 `overlay off`.
- 찍은 그림을 보지 않고 "됐다"고 하지 않는다.
- 다 쓰면 서버는 20분 뒤 저절로 끝난다. 렌더러를 다시 빌드할 일이 있으면 빌드 스크립트가 알아서 끝낸다.
